We set up Vitest at the start of this section. Here are some useful options you will need once the tests are in a real project.

# THE DEFAULTS

For new CLI projects, the default test runner is Vitest, with "jsdom" included to simulate the browser. "happy-dom" is an alternative. Karma is still supported, and the Angular docs link to a migration guide if you are moving from Karma and Jasmine.

"ng test" runs in watch mode.

The configuration lives in the "test" target of "angular.json", which uses the "@angular/build:unit-test" builder. Some of its options are "include", "exclude", "setupFiles", "providersFile", "coverage", "browsers" and "runnerConfig". To get a Vitest config file you can edit -

    ng generate config vitest

# RUNNING ON A BUILD SERVER (CI)

    ng test --no-watch --no-progress

Setting the environment variable "CI=true" also switches to a single run.

# COVERAGE

    ng test --coverage

# BROWSER MODE

Instead of jsdom, you can run tests in a real browser. Install a provider, for example "@vitest/browser-playwright" together with "playwright" (or the WebdriverIO equivalent), then -

    ng test --browsers=chromium

Use "chromiumHeadless" if you do not want a visible window.

You can read more on the official Angular website - https://angular.dev/guide/testing
