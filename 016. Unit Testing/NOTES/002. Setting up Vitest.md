So, now that we have decided to use "Vitest" for testing, how to set it up in our Angular project?

If you have created a new project with Angular 21 or above, then you do not have to do anything. Vitest is already set up for you and you can just run "ng test". But, if you have an older project that still uses "Karma" and "Jasmine", then you can follow the steps below to move to Vitest. These are also the things that are already done in the project of this section, so that you know what to look for.

# STEP #1 - INSTALL PACKAGES

We need to install two packages using npm. 

We of course need to install the "vitest" package.

Along with that, we need a library that will emulate the browser's DOM in Node.js. That is the "jsdom" package.

We can install both at once using this command -

    npm i vitest jsdom -D

Note that we are using "-D" flag which means we are installing these as "Dev" dependencies.

(If you want, you can use "happy-dom" instead of "jsdom". The Angular CLI uses "happy-dom" if it is installed, otherwise it uses "jsdom".)

# STEP #2 - UNINSTALL PACKAGES

Now that we have done this, we no longer require the "Karma" and "Jasmine" packages so we can remove all of them from package.json. For this, we can use this one command - 

    npm uninstall @types/jasmine jasmine-core karma karma-chrome-launcher karma-coverage karma-jasmine karma-jasmine-html-reporter

# STEP #3 - UPDATE THE TEST BUILDER IN ANGULAR.JSON

There is still a reference to "Karma" in the angular.json file. Find the "test" object under "architect" of your project and make it like this - 

    "test": {
      "builder": "@angular/build:unit-test"
    }

The "@angular/build:unit-test" builder is the one that runs our tests. It uses Vitest as the default test runner (the "runner" option has the value "vitest" by default). If you want to keep using Karma with this builder, you can set the "runner" option to "karma".

# STEP #4 - UPDATE TSCONFIG.SPEC.JSON FILE

Inside the tsconfig.spec.json file, you will see "jasmine" in the array for "types" property. Remove it and in its place write - 

    "types": [
      "vitest/globals"
    ]

This tells TypeScript about the global functions of Vitest, like "describe", "it", "expect" and "beforeEach", so that we can use them in our spec files without importing them.

# STEP #5 - UPDATE THE SCRIPTS IN PACKAGE.JSON

The "test" script in package.json is just the Angular CLI command -

    "test": "ng test"

We can also create one more script to run the tests only once (without watching the files) which is useful on CI servers -

    "test:ci": "ng test --no-watch"

Here, by default, "ng test" runs in "watch mode" in a terminal. It means as we make changes to the files, it will automatically run the tests again. The "--no-watch" flag runs all the tests once and exits.

# AND WE ARE DONE

And we are done with the setup. There is no config file for Vitest, nothing like "jest.config.js" or "setup-jest.ts", because the Angular CLI creates the configuration for us from the angular.json file.

(If you have an older project that was using Jest, you can delete the "jest.config.js" and "setup-jest.ts" files, and uninstall the jest packages - "jest", "jest-preset-angular" and "@types/jest".)

Now, if you run the command "npm test", it will start Vitest in the watch mode and it will run all the files that end with ".spec.ts" in the project.

If there are no spec files, then it will say that no tests were found. And that is fine because we have not written any tests yet. But, it means that Vitest is configured properly and we can use it to write and run tests.

# SOME USEFUL OPTIONS

 - ng test --coverage -> Generates the code coverage report in the "coverage" folder (you need to install the "@vitest/coverage-v8" package for this).
 - ng test --include src/app/shared/utils/utils.spec.ts -> Runs only the tests of a specific file.
 - ng test --browsers=chromium -> Runs the tests in a real browser instead of jsdom. This needs a browser provider like Playwright to be installed.
