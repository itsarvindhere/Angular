Reactive and template-driven forms know how to talk to native inputs. But what if you build your own control, like a star rating or a custom date picker, and want it to work with "formControlName" and "ngModel" too?

For that we use an interface called "ControlValueAccessor". It is the bridge between a form control and a component.

# THE FOUR METHODS

 - "writeValue(value)" - the form wants to put a value into your component (model to view). Update what you show.
 - "registerOnChange(fn)" - Angular gives you a function. Save it, and call it whenever the user changes the value in your component.
 - "registerOnTouched(fn)" - the same, but you call it when the control is blurred, so the form can mark it "touched".
 - "setDisabledState(isDisabled)" - optional. Called when the form disables or enables the control.

# AN EXAMPLE

    @Component({
        selector: 'app-my-input',
        template: `
            <input [value]="value" (input)="onInput($event)" (blur)="onTouched()" />
        `,
        providers: [{
            provide: NG_VALUE_ACCESSOR,
            useExisting: forwardRef(() => MyInput),
            multi: true,
        }],
    })
    export class MyInput implements ControlValueAccessor {
        value = '';
        private onChange: (v: string) => void = () => {};
        onTouched: () => void = () => {};

        writeValue(v: string) { this.value = v ?? ''; }
        registerOnChange(fn: (v: string) => void) { this.onChange = fn; }
        registerOnTouched(fn: () => void) { this.onTouched = fn; }
        setDisabledState(isDisabled: boolean) { /* reflect it in the template */ }

        onInput(event: Event) {
            this.onChange((event.target as HTMLInputElement).value);
        }
    }

Now it works like any other field -

    <app-my-input formControlName="name" />

The "NG_VALUE_ACCESSOR" provider is what tells Angular "this component is a form control". It is the part of the pattern that I could not find on the official API page, so confirm it against the current docs for your Angular version.

# COMPARE WITH SIGNAL FORMS

In the Signal Forms notes (custom controls) a custom control only needs a "value" model signal, and no provider or callbacks. Angular's Signal Forms guide also says such controls work with Reactive and Template-driven forms, so for new components that is the simpler way.

You can read more on the official Angular website - https://angular.dev/api/forms/ControlValueAccessor
