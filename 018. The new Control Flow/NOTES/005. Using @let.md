The new control flow gives us "@if", "@for" and "@switch". Angular also gave us one more small but very useful piece of template syntax - "@let".

"@let" lets you declare a variable right inside the template and reuse it. Before this, if you needed the same value many times in a template, you had to repeat the expression, or wrap everything in an "*ngIf" with "as", or compute it in the component class.

The syntax is -

    @let name = expression;

For example -

    @let greeting = 'Hello, ' + name;
    <h1>{{ greeting }}</h1>

# THE MOST COMMON USE - THE ASYNC PIPE

Without "@let", reading an observable more than once means either subscribing multiple times or using the "*ngIf ... as" trick -

    <div *ngIf="user$ | async as user">
        {{ user.name }}
    </div>

With "@let" we can write -

    @let user = user$ | async;

    @if (user) {
        <h1>{{ user.name }}</h1>
        <p>{{ user.email }}</p>
    }

The async pipe runs only once, and we use the result in as many places as we want.

# GIVING A LONG EXPRESSION A NAME

    @let fullName = user.firstName + ' ' + user.lastName;

    <p>{{ fullName }}</p>
    <input [value]="fullName" />

The value is kept up to date with the expression, the same way a normal binding is.

# THINGS TO REMEMBER

 - "@let" is read-only inside the template. You cannot reassign it, for example (click)="value = value + 1" is not allowed.
 - It is scoped to the current view and its children. Blocks like "@if", "@for" and "@defer" create new views, so something declared inside an "@if" block is not available after that block ends. It is not hoisted either, so you must declare it before you use it.
 - Declare one variable per "@let". The expression can span multiple lines.

You can read more on the official Angular website - https://angular.dev/guide/templates/variables
