In the previous note we saw that Angular sanitizes values on its own. Sometimes that gets in the way. For example, you have a URL you know is safe but Angular changes it, or you must embed a video iframe whose address comes from a variable.

For this, Angular gives us the "DomSanitizer" service.

# SANITIZING MANUALLY

If you work with the DOM directly (not through a template), you can ask Angular to sanitize a value for a given context -

    private sanitizer = inject(DomSanitizer);

    const safe = this.sanitizer.sanitize(SecurityContext.HTML, userInput);

# TURNING THE PROTECTION OFF - bypassSecurityTrust*

There is one method per context -

 - "bypassSecurityTrustHtml"
 - "bypassSecurityTrustScript"
 - "bypassSecurityTrustStyle"
 - "bypassSecurityTrustUrl"
 - "bypassSecurityTrustResourceUrl"

Example - an iframe needs a "Resource URL" -

    private sanitizer = inject(DomSanitizer);
    videoUrl = this.sanitizer.bypassSecurityTrustResourceUrl(
        'https://www.youtube.com/embed/' + this.videoId
    );

    <iframe [src]="videoUrl"></iframe>

# THE RULES

The names start with "bypass" for a reason. You are telling Angular "I have checked this, do not protect me". So -

 - Pick the method that matches where the value is used.
 - Only trust values you have inspected, and build them as close to the original data as possible.
 - Never pass raw user input to a "bypassSecurityTrust*" method.
 - Treat every such call in your code as something that needs a review.

You can read more on the official Angular website - https://angular.dev/best-practices/security
