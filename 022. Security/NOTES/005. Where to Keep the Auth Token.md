Status: this is general web-security advice, not an Angular feature. The Angular security guide says clearly that it does not cover authentication or authorization.

In the Authentication section we saved the logged-in user, including the token, in "localStorage" so that auto-login works after a refresh. This is simple and fine for learning, but it is good to know the trade-off.

 - Anything in "localStorage" can be read by any script running on your page. So if an XSS bug ever lets an attacker run a script, they can steal the token. That is why the earlier notes about XSS matter.
 - A cookie marked "HttpOnly" cannot be read by JavaScript at all. The browser sends it automatically with requests. That protects against token theft by scripts, but then you need XSRF protection (see the XSRF note).
 - A short-lived token limits the damage if it leaks. Firebase ID tokens, for example, expire after about an hour, which is why our app has auto-logout.

So, for a real production app -

 - Prefer an "HttpOnly", "Secure" cookie set by your server, if your backend supports sessions.
 - Keep tokens short-lived.
 - Add a Content Security Policy to make XSS harder.
 - Never log tokens or put them in URLs you share. (Our Firebase example sends the token in the URL query only because the Firebase REST API expects it.)
