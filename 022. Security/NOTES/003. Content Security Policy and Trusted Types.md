Sanitizing helps, but it is a good idea to also add a second layer of defence in the browser. That is what a Content Security Policy (CSP) does. It is an HTTP header that tells the browser which scripts and styles are allowed to run.

Angular's documentation gives this minimal policy as a starting point for a new app -

    default-src 'self'; style-src 'self' 'nonce-randomNonceGoesHere'; script-src 'self' 'nonce-randomNonceGoesHere';

The "nonce" is a random value that your server puts in the header and in the page. Only inline scripts and styles with that nonce are allowed.

# GIVING THE NONCE TO ANGULAR

Angular adds some styles to the page itself, so it needs to know the nonce. There are two ways -

 1. The "ngCspNonce" attribute on the root element -

        <app ngCspNonce="randomNonceGoesHere"></app>

 2. The "CSP_NONCE" injection token -

        bootstrapApplication(App, {
            providers: [{ provide: CSP_NONCE, useValue: myNonce }],
        });

Rules for the nonce -

 - It must be unique for every request and impossible to guess.
 - Behind a CDN that caches your HTML, the same nonce would repeat for everyone. In that case, a CDN-friendly option is needed (see "security.autoCsp" in the docs).
 - "CSP_NONCE" cannot be used if you inline critical CSS. Use "ngCspNonce" or auto CSP instead.

# TRUSTED TYPES

Trusted Types is a browser feature that blocks dangerous DOM writes (like setting "innerHTML") unless they go through an approved policy. Angular recommends it. You turn it on with a header -

    Content-Security-Policy: trusted-types angular; require-trusted-types-for 'script';

Angular's policy names are "angular", "angular#bundler", "angular#unsafe-bypass", "angular#unsafe-jit" and "angular#unsafe-upgrade". You need "angular#unsafe-bypass" if you use any "bypassSecurityTrust*" method.

Remember that the header must also be sent during "ng serve" (you can set headers in angular.json) so you notice problems early.

You can read more on the official Angular website - https://angular.dev/best-practices/security
