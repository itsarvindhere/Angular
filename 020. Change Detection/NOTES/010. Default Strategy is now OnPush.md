Status: Angular 22 changed the default. This note explains what changed and why old code might behave differently.

Until Angular 21, if you did not set "changeDetection" in a component, Angular used the "Default" strategy - the component was checked every time change detection ran.

Since Angular 22, a component that does not set "changeDetection" uses "OnPush". So -

    @Component({
        selector: 'app-card',
        template: `...`,
    })
    export class CardComponent {}

is now the same as writing "changeDetection: ChangeDetectionStrategy.OnPush".

# WHAT TRIGGERS A CHECK WITH ONPUSH

A component is checked when -

 - an input changes through a template binding;
 - an event listener in the component fires;
 - "markForCheck()" is called, or the async pipe receives a value;
 - a signal read in the template changes.

(This is the same list we saw in the OnPush note, it just applies everywhere by default now.)

# KEEPING THE OLD BEHAVIOUR

If an existing component relies on being checked every cycle, for example because it mutates objects or fields without signals, you can opt back in with the new "Eager" strategy -

    @Component({
        selector: 'app-legacy',
        changeDetection: ChangeDetectionStrategy.Eager,
        template: `...`,
    })

"Eager" means the component is checked whenever change detection traverses it. The old name "ChangeDetectionStrategy.Default" still exists, but it is deprecated and is simply equivalent to "Eager".

# WHAT THIS MEANS FOR US

 - Using signals, "async" pipe and immutable data works great with the new default.
 - If a screen stopped updating after upgrading to Angular 22, check whether it mutates plain properties. Move the state to signals, or mark the component "Eager" as a temporary fix.

You can read more on the official Angular website - https://angular.dev/guide/components/advanced-configuration
