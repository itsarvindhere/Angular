This section comes with a small project, "error-handling-final", that has a button for every kind of error we talked about. Open its README for a table that points from each note to the code.

# WHAT YOU CAN TRY

Press the buttons and watch the table at the bottom, which shows what the global "ErrorHandler" received.

 - Buttons 1 to 4 - an error in a click handler, an unhandled promise rejection, an error inside "setTimeout" and an error inside the async pipe. All four reach the global handler. Numbers 2 and 3 get there because of "provideBrowserGlobalErrorListeners()".
 - Button 5 - bad JSON caught with "try/catch". The user sees a message, and the global handler sees nothing.
 - Button 6 - a request to a server that is down, with "httpResource". The page shows the error from the resource's own "error()" state. The global handler sees nothing, because a resource does not forward its errors.

Compare the two groups. Unexpected errors go to the global handler so that you can log them. Expected errors are handled where they happen, so the user gets a useful message.

Remove "provideBrowserGlobalErrorListeners()" from "app.config.ts" and press buttons 2 and 3 again. They no longer show up in the table.
