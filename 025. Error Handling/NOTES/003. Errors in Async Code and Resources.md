Where an error goes depends on how the async code was started.

 - The "async" pipe forwards errors from its observable to the "ErrorHandler".
 - "PendingTasks.run" also forwards errors to the "ErrorHandler".
 - "resource" does NOT forward errors. It keeps them in its own state, so your template must read them.

Example with a resource -

    postsResource = httpResource<Post[]>(() => '/api/posts');

    @if (postsResource.error()) {
        <p>Could not load posts.</p>
    } @else if (postsResource.isLoading()) {
        <p>Loading...</p>
    } @else {
        @for (post of postsResource.value(); track post.id) {
            <app-post [post]="post" />
        }
    }

This is the same resource we used in the Signals section. If you never read "status" or "error", a failure can go unnoticed, because the global handler will not see it.

# A SIMPLE RULE

 - Expected failures (a request fails, a form is invalid) - handle them where they happen, and show the user a message.
 - Unexpected failures (a bug) - let them reach the "ErrorHandler" and log them.

You can read more on the official Angular website - https://angular.dev/best-practices/error-handling
