When code throws an error and nobody catches it, Angular sends it to a service called "ErrorHandler". The default one writes it to the console.

You can replace it to do something more useful, like sending the error to a tracking service.

    export class GlobalErrorHandler implements ErrorHandler {
        private router = inject(Router);

        handleError(error: any) {
            const url = this.router.url;
            const message = error?.message ?? 'unknown';
            // send url and message to your tracking service
            console.error('Unhandled error', { url, message, error });
        }
    }

Register it where you bootstrap the app -

    bootstrapApplication(App, {
        providers: [{ provide: ErrorHandler, useClass: GlobalErrorHandler }],
    });

# WHAT IT CATCHES

Angular catches errors in code it runs itself: constructors, lifecycle hooks and template expressions. It does not catch errors in your own methods that you call from elsewhere, for example a service method. For those, use "try/catch" or the "catchError" operator, like we did in the HTTP section.

# WHEN TO USE IT

The docs describe "ErrorHandler" as being for unexpected, potentially fatal errors - logging and telemetry. Handle expected errors (like a failed request) at the place where they happen, so the user can see a useful message.

You can read more on the official Angular website - https://angular.dev/best-practices/error-handling
