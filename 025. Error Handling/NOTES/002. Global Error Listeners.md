Some errors do not happen inside Angular code at all. For example, a promise somewhere rejects and nobody handles it, or a script throws in a timer. The browser reports these as "error" and "unhandledrejection" events on the window.

"provideBrowserGlobalErrorListeners()" adds listeners for these two events and forwards them to the "ErrorHandler". That way your custom handler from the previous note sees them too.

    bootstrapApplication(App, {
        providers: [provideBrowserGlobalErrorListeners()],
    });

The Angular CLI adds this to new apps by default. If you write your own window listeners, you can remove it.

# ON THE SERVER (SSR)

Angular adds "unhandledRejection" and "uncaughtException" listeners on the server. If you use Zone.js, only "unhandledRejection" is added.

You can read more on the official Angular website - https://angular.dev/best-practices/error-handling
