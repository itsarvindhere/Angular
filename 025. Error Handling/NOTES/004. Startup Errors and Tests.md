Two small gotchas with the "ErrorHandler".

# ERRORS DURING STARTUP

An error that is thrown before the root Angular instance exists skips the "ErrorHandler", because it does not exist yet. The docs say this matters most for Angular elements. Ways around it are to delay the code with "setTimeout", or to use "APP_BOOTSTRAP_LISTENER" or "ngDoBootstrap".

# ERRORS IN TESTS

By default, "TestBed" rethrows unexpected errors so that your test fails instead of hiding the problem. That is what you want most of the time. If a test must keep running after an error, you can switch this off -

    TestBed.configureTestingModule({
        rethrowApplicationErrors: false,
    });

You can read more on the official Angular website - https://angular.dev/best-practices/error-handling
