By default the code for every route is in the first download. Lazy loading means a route's code is downloaded only when the user goes there, which makes the first load faster.

With standalone components, we do this with "import()" and two route properties.

# loadComponent - ONE COMPONENT

    { path: 'login', loadComponent: () => import('./auth/login-page') },

# loadChildren - A GROUP OF ROUTES

    { path: 'admin', loadChildren: () => import('./admin/admin.routes') },

The file "admin.routes.ts" exports an array of routes. (For this short form, the component or the routes must be the default export of that file.)

The loader functions run in the route's injection context, so you can use "inject()" inside them.

The Angular docs suggest loading landing pages eagerly and lazy loading the rest.

(The older NgModule way is in the Legacy Modules section.)

# ROUTE-LEVEL PROVIDERS

A route can have its own "providers". A service listed there is created for that route and its children, not for the whole app -

    {
        path: 'admin',
        loadChildren: () => import('./admin/admin.routes'),
        providers: [AdminService],
    }

This is a good fit together with lazy loading, because the service code also stays out of the first download.
