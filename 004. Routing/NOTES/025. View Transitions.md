Modern browsers have a built-in View Transitions API ("document.startViewTransition") that animates between two states of the page. The Angular router can use it for route changes, so you get smooth navigation animations with very little code.

In Angular 22.3, "withViewTransitions" is stable.

# ENABLING IT

    import { provideRouter, withViewTransitions } from '@angular/router';

    bootstrapApplication(AppComponent, {
        providers: [provideRouter(routes, withViewTransitions())],
    });

(In an NgModule-based app, the equivalent is "RouterModule.forRoot(routes, { enableViewTransitions: true })".)

By default, the browser cross-fades the old and new page. You can customise the animation with CSS, using the "::view-transition-old(root)" and "::view-transition-new(root)" pseudo-elements.

# BROWSER SUPPORT

If the browser does not support view transitions, the router just navigates normally without animation. So it is safe to turn on.

# OPTIONS

"withViewTransitions" accepts an "onViewTransitionCreated" callback, which runs in an injection context and gives you the transition object. For example, you can skip the animation for users who prefer reduced motion -

    withViewTransitions({
        onViewTransitionCreated: ({ transition }) => {
            if (matchMedia('(prefers-reduced-motion: reduce)').matches) {
                transition.skipTransition();
            }
        },
    })

The router does not check "prefers-reduced-motion" for you, so this is worth adding.

You can read more on the official Angular website - https://angular.dev/guide/routing/route-transition-animations
