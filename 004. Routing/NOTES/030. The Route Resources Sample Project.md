The previous two notes come with a small project, "route-resources-final", in the Routing section. Open its README for the list of things to try. It uses a slow fake backend, so you can see the timing on the page.

# WHAT IT SHOWS

 - Parallel against sequential. The same user page is built twice, once with route resources and once with resolvers. The navigation takes about 800 milliseconds with resources, because the parent and the child load at the same time. With resolvers it takes about 1400 milliseconds, because the child waits for the parent.
 - Reactive loading. Changing the "range" query parameter re-runs only the activity resource. The request counter at the top shows that the user was not loaded again.
 - A non-blocking resource. The feed page appears in a few milliseconds and shows "Loading the feed..." itself.
 - Two kinds of failure. A failing non-blocking resource shows its error inside the page. A failing blocking resource ("Unknown user") cancels the navigation, and you stay where you were.
 - An error boundary. A page that throws while it is being created is replaced by a fallback page.

Both features are in developer preview, so check the Angular docs before using them in a real project.
