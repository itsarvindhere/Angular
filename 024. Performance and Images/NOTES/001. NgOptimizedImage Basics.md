Images are usually the heaviest part of a page, and the biggest image is often the "LCP" (Largest Contentful Paint) element, the thing Google measures to decide how fast your page feels.

Angular has a directive that applies many image best practices automatically - "NgOptimizedImage".

    import { NgOptimizedImage } from '@angular/common';

    @Component({
        imports: [NgOptimizedImage],
        template: `<img ngSrc="cat.jpg" width="400" height="200" />`,
    })

# USE ngSrc, NOT src

The docs say that if you also use "src", the browser starts downloading the image eagerly before the directive can adjust "loading". So use "ngSrc" only.

# WIDTH AND HEIGHT

They are required (unless you use "fill"), because they let the browser reserve space and avoid layout shift.

 - For a fixed-size image, use the size at which it is displayed, keeping the file's aspect ratio.
 - For a responsive image, use the file's intrinsic size and add "sizes" (see the next note).

# priority - MARK THE LCP IMAGE

    <img ngSrc="hero.jpg" width="1200" height="600" priority />

This sets "fetchpriority=high", "loading=eager" and "decoding=sync", and under SSR it also generates a preload link. Every other image is lazy loaded by default. The LCP element can differ between phone and desktop, so you may need "priority" on more than one image.

# fill - WHEN YOU DO NOT KNOW THE SIZE

    <div class="box">
        <img ngSrc="cat.jpg" fill />
    </div>

The parent must have "position: relative" (or "fixed" or "absolute"). Use CSS "object-fit" (contain or cover) to control how the image fits.

# IN DEVELOPMENT MODE

The directive warns you about things like a missing "priority" on the LCP image, wrong width and height, a distorted aspect ratio and a missing preconnect.

Not supported: CSS "background-image" and the "<picture>" element.

You can read more on the official Angular website - https://angular.dev/guide/image-optimization
