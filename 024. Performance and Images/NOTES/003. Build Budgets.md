A bundle that was fast at the start can slowly grow as you add libraries. Build budgets catch that early. They are limits you set in "angular.json", and "ng build" prints a warning or fails if you go over them.

    "configurations": {
        "production": {
            "budgets": [
                { "type": "initial", "maximumWarning": "250kb", "maximumError": "500kb" },
                { "type": "anyComponentStyle", "maximumWarning": "4kb", "maximumError": "8kb" }
            ]
        }
    }

# BUDGET TYPES

 - "initial" - the JavaScript and CSS needed to start the app (the "Initial total" you see in the build output). Default limits are a 500kb warning and a 1mb error.
 - "anyComponentStyle" - the size of a single component's CSS. Defaults are a 4kb warning and an 8kb error.
 - "bundle" - one named bundle, for example a lazy-loaded one. It needs a "name".
 - "allScript", "all", "anyScript", "any" - other groupings.

# LIMITS

"maximumWarning" and "maximumError" are the common ones. There are also "minimumWarning" and "minimumError", plus "baseline", "warning" and "error". Values can be bytes ("123" or "123b"), "kb", "mb", or a percentage of the baseline.

    { "type": "bundle", "name": "admin", "maximumWarning": "250kb", "maximumError": "300kb" }

# WHEN A BUDGET FAILS

Do not just raise the number. Look at what grew - a new library, a large import that could be lazy loaded with a route or "@defer", or an unused dependency. (I could not verify from the Angular docs which tool to use to inspect bundle contents, so check the current CLI documentation for its analysis options.)

You can read more on the official Angular website - https://angular.dev/reference/configs/workspace-config
