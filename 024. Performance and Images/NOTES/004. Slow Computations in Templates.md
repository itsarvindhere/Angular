In the Change Detection section we learned that Angular checks the template every time change detection runs. Everything in the template is evaluated again - function calls, getters and pipes with changing input.

If one of those is slow, the whole page feels slow, because change detection runs synchronously.

The work Angular does during a check includes evaluating template expressions and running "ngDoCheck", "ngAfterContentChecked", "ngAfterViewChecked" and "ngOnChanges". So anything heavy inside them runs a lot.

# WHAT THE DOCS SUGGEST

 1. Optimize the algorithm first. Often the code itself can be made faster.
 2. Move heavy work into a pure pipe. A pure pipe re-runs only when its input changes, not on every check.
 3. Use memoization, which caches results by input. It costs memory, so use it knowingly.
 4. Avoid reading or writing the layout in lifecycle hooks, because it forces the browser to recalculate layout.

Compare -

    <!-- runs on every change detection -->
    <p>{{ expensiveSort(items) }}</p>

    <!-- runs only when "items" is a new value -->
    <p>{{ items | expensiveSort }}</p>

Better still, compute the value once with a "computed" signal and read it in the template.

# FIND THE PROBLEM FIRST

Use the Angular DevTools profiler to see which components take time, and fix those. Do not guess.

You can read more on the official Angular website - https://angular.dev/best-practices/slow-computations
