This section comes with a small project, "performance-final", that shows the ideas from the previous notes on one page. Open its README for a table that points from each note to the code.

# WHAT YOU CAN TRY

 - See the blur placeholder. On your own computer images load instantly, so the placeholder is gone before you can notice it. Start the small "slow image" server with "npm run slow-images" and open the page with "?slow" at the end of the address. The second image first shows a tiny blurred version, and the real one replaces it a few seconds later. This is the effect your visitors get on a slow phone connection.
 - Look at the table in section 4 of the page. It reads the "img" elements after the page has rendered and shows what "NgOptimizedImage" generated. The "priority" image is eager with a high fetch priority, and the others are lazy.
 - Type in the text box in section 5, then press "Refresh counts". The same calculation is done three ways - a method call in the template, a pure pipe and a "computed" signal. The method ran again and again, while the pipe and the signal ran once.
 - Lower the "initial" budget in "angular.json" to 100kB and run "npm run build". The build fails. This is how a budget protects you.

# TWO ERRORS THAT THE PROJECT TAUGHT US

 1. "sizes" with a fixed pixel width throws error NG02952. Use responsive values like "50vw".
 2. "placeholder" without an image loader throws error NG02963. The unit tests have to provide the same loader as the app, or they fail with this error.
