In the "DestroyRef" note we saw how to run cleanup code when a component is destroyed. A very common cleanup is unsubscribing from an observable so that it does not keep running (and leaking memory) after the component is gone.

The old way was to keep a "Subject", call "takeUntil(this.destroy$)" and then call "next()" in "ngOnDestroy". That is a lot of boilerplate.

Angular gives us a ready-made RxJS operator for this - "takeUntilDestroyed". It lives in "@angular/core/rxjs-interop" and is stable since Angular 19.

    import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

    export class TimerComponent {
        constructor() {
            interval(1000)
                .pipe(takeUntilDestroyed())
                .subscribe((n) => console.log(n));
        }
    }

When the component is destroyed, the subscription is completed automatically. No "ngOnDestroy", no extra Subject.

# INJECTION CONTEXT

When you call "takeUntilDestroyed()" without an argument, it needs to find the current "DestroyRef", so it must be called in an injection context, such as a constructor or a field initializer.

If you want to use it somewhere else, for example inside a method, pass the "DestroyRef" yourself -

    export class TimerComponent {
        private destroyRef = inject(DestroyRef);

        start() {
            interval(1000)
                .pipe(takeUntilDestroyed(this.destroyRef))
                .subscribe((n) => console.log(n));
        }
    }

This is the same "DestroyRef" we learned about in the previous note, just wrapped in a convenient operator.

Tip - it should usually be the last operator in the pipe, just before "subscribe".

You can read more on the official Angular website - https://angular.dev/api/core/rxjs-interop/takeUntilDestroyed
