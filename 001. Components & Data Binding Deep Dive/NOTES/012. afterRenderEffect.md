In the earlier note we learned about "afterEveryRender" and "afterNextRender". There is a third render hook that combines the render hooks with signals - "afterRenderEffect".

It registers an effect that runs after Angular has finished rendering. Like the other render hooks -

 - it runs only in the browser, never on the server (SSR);
 - it should be called in an injection context, typically the constructor.

The difference is that "afterRenderEffect" tracks signals. It runs at least once, and after that it runs again only when one of the signals it reads has changed. "afterEveryRender" in contrast runs after every render, whether anything changed or not.

# BASIC FORM

    constructor() {
        afterRenderEffect(() => {
            console.log('Count is', this.count());
        });
    }

# PHASES

Reading from and writing to the DOM in the wrong order causes layout thrashing. To control this, you can pass an object with "phases". They always run in this order -

 1. earlyRead
 2. write
 3. mixedReadWrite
 4. read

Example - resizing an element and then measuring it -

    constructor() {
        afterRenderEffect({
            write: () => {
                this.box().nativeElement.style.height = this.height() + 'px';
            },
            read: () => {
                console.log(this.box().nativeElement.offsetHeight);
            },
        });
    }

Each phase after the first receives the value returned by the previous phase as a signal.

Rules of thumb -

 - Do not write to the DOM in "earlyRead" or "read".
 - Do not read from the DOM in "write".
 - Avoid "mixedReadWrite" when you can split the work into the other phases. If you pass a plain callback, it runs in "mixedReadWrite", so using an explicit phase is better.

You can read more on the official Angular website - https://angular.dev/api/core/afterRenderEffect
