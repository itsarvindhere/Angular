In Angular 22, we got a new decorator for services - 'Service'.

Before Service decorator, we used to use the 'Injectable' decorator but at first glance, someone would find it hard to understand what this decorator meant for a class.

A class with an 'Injectable' decorator is a Service in Angular. Hence, to make things simple, we now have a 'Service' decorator that we can use instead of 'Injectable.

The migration is pretty simple.

Earlier, we would use -

    @Injectable({ providedId: 'root' })
    export class SomeService {}

This meant 'SomeService' is registered globally with the application's root injector. So, Angular creates only one instance of this service across the entire application.  of the service across your entire application. Every component, directive, or other service that injects this dependency will share the exact same instance and data state.

With the new 'Service' decorator, this can now be done simply by -

    @Service()
    export class SomeService {}

This clearly tells us that 'SomeService' is actually an Angular service.

But, what about those cases where we used Injectable as -

    @Injectable()
    export class SomeService {}

When we use the @Injectable() decorator in Angular without the 'providedIn' property, we are creating a service that is not automatically registered with the application's root dependency injection (DI) system.

So, how to migrate this to 'Service' decorator? Well, in that case, we need to pass an additional option named 'autoProvided' and set it to false -

    @Service({ autoProvided: false })
    export class SomeService {}

This means, by default, the Service decorator always provides the class at the root injector. If we want to provide it manually, for example, to scope it to a specific route or component, set autoProvided: false.

# THERE IS A CATCH

One thing worth mentioning is that you cannot just blindly replace Injectable with Service decorator. There is one important thing to mention.

A class using the 'Service' decorator can only be injected using the 'inject' function. It does not support injecting using constructor-based injection.

So, if you have a service that is injected using constructor-based injection and you do not want to use 'inject' function (for some reasons), you have to keep using the 'Injectable' decorator for now.

Also, for non-root scopes such as -

    providedIn: 'platform'

You still have to keep using the 'Injectable' decorator.

Finally, if you are using 'Injectable' decorator with advanced provider configurations like useClass, useValue, useExisting, or useFactory, then you have to keep using 'Injectable' since the 'Service' decorator only exposes one option and that is 'factory'.

So, that is all about the new 'Service' decorator in Angular 22. Note that 'Injectable' is not deprecated, for now. So, you can continue using it in your applications if you cannot migrate to 'Service' decorator.
