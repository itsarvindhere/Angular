So far, we have been getting our dependencies using the constructor -

    constructor(private loggingService: LoggingService) {}

This is the traditional way, and you will find it in a lot of existing code. But, Angular also provides a function named "inject()" which does the same thing and is now the recommended way in modern Angular code.

# USING INJECT()

    import { Component, inject } from '@angular/core';

    export class AppComponent {
        private loggingService = inject(LoggingService);
    }

That's it. We do not need a constructor at all. Angular looks at the injectors, finds "LoggingService" and gives it to us, exactly like it would do for a constructor parameter.

We can inject tokens too, like the ones we created in the Injection Tokens section -

    private apiUrl = inject(API_URL);

# WHERE CAN WE CALL INJECT()?

We can only call inject() inside an "injection context". This is a place where Angular is currently creating something and has access to an injector. These are -

    - The constructor of a class created by Angular (component, directive, pipe, service).
    - The initializer of a class field (like the examples above).
    - A factory function used while providing a dependency (useFactory).
    - A function that is called from one of these places.
    - Functions that Angular runs for us in an injection context, such as functional route guards, resolvers and HTTP interceptors.

If we try to call inject() anywhere else (for example, inside ngOnInit or inside a click handler), we get an error saying that inject() must be called from an injection context.

If we ever need to use it outside of such a place, we can grab the Injector first and use "runInInjectionContext" -

    private injector = inject(Injector);

    onClick() {
        runInInjectionContext(this.injector, () => {
            const service = inject(SomeService);
        });
    }

# OPTIONS

The inject() function accepts a second argument with the same options that we used to have as decorators (@Optional, @Self, @SkipSelf and @Host) -

    private logger = inject(LoggingService, { optional: true });
    private parentLogger = inject(LoggingService, { skipSelf: true });

With "optional: true", we get "null" instead of an error when nothing provides the dependency.

# WHY IS IT BETTER THAN THE CONSTRUCTOR?

    1. Less code. No constructor, no "private" parameter properties.
    2. Types are inferred automatically from the token.
    3. Inheritance becomes simple. A child class does not need to receive all the services in its constructor just to pass them to super().
    4. We can write reusable functions that use inject() inside them.

For example, we can write a small helper -

    export function injectLogger() {
        const logger = inject(LoggingService);
        return (msg: string) => logger.log('[App] ' + msg);
    }

And then use it from any component -

    private log = injectLogger();

# FUNCTIONAL GUARDS AND INTERCEPTORS

The functional guards and interceptors that we use in the Routing and HTTP sections have no constructor at all. inject() is the way they get their dependencies -

    export const authGuard: CanActivateFn = () => {
        const authService = inject(AuthService);
        const router = inject(Router);
        return authService.isLoggedIn() ? true : router.createUrlTree(['/']);
    };
