In a normal website, clicking a link loads a new page and the screen reader starts reading from the top. In a single-page app, the router changes the content without a reload, so a screen reader user may hear nothing, and keyboard focus can end up lost on the page.

# MOVE FOCUS AFTER NAVIGATION

The Angular docs suggest listening to the router and moving focus to the main heading of the new page -

    constructor() {
        inject(Router).events
            .pipe(filter((e) => e instanceof NavigationEnd))
            .subscribe(() => {
                document.querySelector<HTMLElement>('#main-content-header')?.focus();
            });
    }

The goal is that focus does not fall back to the "<body>". (The target element needs "tabindex="-1"" to accept focus from code.)

# MARK THE ACTIVE LINK

With "routerLinkActive" you can also tell assistive technology which link is the current page -

    <a routerLink="/about" routerLinkActive="active" ariaCurrentWhenActive="page">About</a>

# LIVE CONTENT

If a part of the page updates without navigation, for example a "@defer" block that loads later, put it inside an ARIA live region so screen readers announce the change.

You can read more on the official Angular website - https://angular.dev/best-practices/a11y
