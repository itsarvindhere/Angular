Accessibility (often written "a11y") means making sure everyone can use your app, including people who use screen readers or only the keyboard.

# START WITH NATIVE ELEMENTS

A real "<button>" already works with the keyboard, has the right role for screen readers and gets focus. A "<div (click)>" has none of that. So -

 - Use "<button>" for actions and "<a>" for navigation.
 - If you build a custom button component, use an attribute selector on the native element instead of replacing it -

        @Component({
            selector: 'button[app-action]',
            template: `<ng-content />`,
        })
        export class ActionButton {}

   and use it as "<button app-action>Save</button>".
 - For form fields, keep the native "<input>" and wrap it in a container using content projection (this is how Angular Material's form field works).

# BINDING ARIA ATTRIBUTES

ARIA attributes bind like any other attribute -

    <button [aria-label]="myActionLabel">...</button>

Static ones are plain attributes -

    <button aria-label="Close dialog">...</button>

Some ARIA properties take element references. For these, use property binding -

    <div role="dialog" [ariaLabelledByElements]="[dialogTitle, dialogDescription]">

And inside a component, "host" is a convenient place to keep ARIA state in sync with a signal -

    @Component({
        selector: 'app-progress',
        host: { '[attr.aria-valuenow]': 'value()' },
        template: `...`,
    })

You can read more on the official Angular website - https://angular.dev/best-practices/a11y
