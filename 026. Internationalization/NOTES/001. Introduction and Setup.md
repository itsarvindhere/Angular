Internationalization (often written "i18n", because there are 18 letters between the "i" and the "n") means preparing your app so it can be shown in more than one language and locale. Localization is the step where you actually provide the translations.

Angular's built-in approach is a compile-time one. The build compiles your app once with AOT, and the i18n markers become "$localize" calls. Then the translations are applied after compilation, so one compile can produce a separate build for every language - "compile once, then translate for each locale".

# THE STEPS

 1. Add the package.
 2. Mark the text in templates and code that should be translated.
 3. Extract the text into a translation file ("ng extract-i18n").
 4. Send that file to translators, and put their translated files back in the project.
 5. Tell "angular.json" about the languages, and build.

# ADDING THE PACKAGE

    ng add @angular/localize

This adds "@angular/localize" to the TypeScript configuration and a reference to it in "main.ts". If you try to build with i18n attributes without this package, the CLI stops with an error and tells you the setup steps.

There is an option, "--use-at-runtime" (default false). It makes "$localize" usable at runtime, and moves the package from "devDependencies" to "dependencies". You only need it if you want to translate text at runtime.

Note - "AOT" must be on for template translation. It is the default, so you normally do not have to think about it.

You can read more on the official Angular website - https://angular.dev/guide/i18n
