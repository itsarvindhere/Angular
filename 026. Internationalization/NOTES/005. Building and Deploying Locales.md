Once the translation files are listed in "angular.json", the build can produce the translated app.

# BUILDING

In the build options, the "localize" setting decides which locales to build -

    "localize": true            // all locales
    "localize": ["fr"]          // only some
    "localize": false           // none

Or from the command line -

    ng build --localize

A common pattern is one configuration per locale -

    "configurations": {
        "fr": { "localize": ["fr"] }
    }

    ng serve --configuration=fr
    ng build --configuration=production,fr

The development server translates only one locale at a time. If several are set, "ng serve" shows a warning and turns localization off, so use a per-locale configuration for it.

# DEPLOYING

Each locale gets its own folder, for example "myapp/fr". When "localize" is used, the CLI sets the "lang" attribute and the "base href" for each build. The base href uses "subPath", which is the locale ID by default.

 - To remove the folder name for one locale, set the sub path to an empty string. A usual choice is to serve the source language from the root -

        "sourceLocale": { "code": "en", "subPath": "" }

 - Your server should redirect visitors to the right folder based on the "Accept-Language" header. The Angular docs show Nginx and Apache examples.
 - With SSR ("outputMode: server") the redirection is automatic. With "outputMode: static", prerendering creates one folder per locale, and your host has to do the redirect.

You can read more on the official Angular website - https://angular.dev/guide/i18n/deploy
