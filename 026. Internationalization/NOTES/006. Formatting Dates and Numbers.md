Translating the words is not enough. Dates, currencies and numbers are written differently around the world - "11/21/2026" in one country is "21.11.2026" in another.

The built-in pipes "DatePipe", "CurrencyPipe", "DecimalPipe" and "PercentPipe" use the app's locale, which comes from the "LOCALE_ID" token. When you build with "localize", Angular sets it for each language for you.

    {{ today | date }}
    {{ amount | currency: 'USD' : 'symbol' : '1.2-2' }}

# OVERRIDING THE LOCALE FOR ONE PIPE

Every one of these pipes has a locale argument. It overrides the global setting for that single use -

    {{ amount | currency: 'USD' : 'symbol' : '1.2-2' : 'de-DE' }}

This is helpful when one part of the page must show a specific format, for example a price in the currency's home format.

One catch, which we found while building the sample project - the app's own languages (like "fr" and "es" in our project) are registered by the build. A locale that is not one of them needs its data registered once, before you use it -

    import localeDe from '@angular/common/locales/de';
    registerLocaleData(localeDe);

Then "| number: '1.2-2' : 'de'" works in every build.

You can read more on the official Angular website - https://angular.dev/guide/i18n/format-data-locale
