To make a piece of text translatable, we mark it.

# IN A TEMPLATE

Add the "i18n" attribute to an element with fixed text -

    <h1 i18n>Hello i18n!</h1>

If you want to translate some text without creating an extra element in the DOM, use "ng-container" -

    <ng-container i18n>Welcome back</ng-container>

# ATTRIBUTES

For an attribute like "title" or "alt", write "i18n-" followed by the attribute name -

    <img [src]="logo" i18n-title title="Angular logo" alt="Angular logo" />

# IN CODE

Text in TypeScript is marked with the "$localize" tag -

    import '@angular/localize/init';

    title = $localize`Hello i18n!`;
    greeting = $localize`Hello ${name}:name:`;

The ":name:" part gives the placeholder a readable name for the translator.

# MEANING, DESCRIPTION AND ID

You can give the translator more information with this format -

    i18n="meaning|description@@customId"

 - "description" - helps the translator understand the context.
 - "meaning" - the same text can mean different things in different places. Texts with the same meaning share an ID, and different meanings get different IDs. The description does not change the ID.
 - "@@customId" - your own ID. In code it looks like -

        $localize`:@@introductionHeader:Hello i18n!`

# WHY A CUSTOM ID?

By default, Angular builds the ID from the text. If you edit the text, the ID changes and old translations no longer match. A custom ID stays the same when the text is edited. The drawback is that a translation can then drift out of date without anyone noticing.

IDs must be unique. If two places use the same ID, they will get the same translation.

# NAMING A PLACEHOLDER IN A TEMPLATE

    {{ username //i18n(ph="name") }}
