We know how to pass a value from parent to child using Signal Inputs, and how to send a value from child to parent using the output() function.

But sometimes, we want both. That is, the parent gives a value to the child, the child can change that value and the parent should automatically know about the new value. This is called "Two-way Binding".

# TRADITIONAL APPROACH

Traditionally, we needed an @Input() and an @Output() whose name was the input name followed by "Change" -

    @Input() value = 0;
    @Output() valueChange = new EventEmitter<number>();

    increment() {
        this.value++;
        this.valueChange.emit(this.value);
    }

And in the parent, we could use the "banana in a box" syntax -

    <app-counter [(value)]="count" />

This is just a short form of -

    <app-counter [value]="count" (valueChange)="count = $event" />

# THE MODEL FUNCTION

With signals, we have a function named "model()" that gives us both the input and the output in one line. It has been stable since Angular 19.

    import { Component, model } from '@angular/core';

    @Component({
        selector: 'app-counter',
        template: `
            <button (click)="decrement()">-</button>
            {{ value() }}
            <button (click)="increment()">+</button>
        `
    })
    export class CounterComponent {
        value = model(0);

        increment() {
            this.value.update(v => v + 1);
        }

        decrement() {
            this.value.update(v => v - 1);
        }
    }

The "value" here is a "ModelSignal". It works like a Signal Input (we read it by calling it as a function), but it is also writable, so we can call set() and update() on it. Whenever we do that, Angular automatically notifies the parent.

# USING IT IN THE PARENT

In the parent, we can bind a signal directly using the banana in a box syntax -

    count = signal(5);

    <app-counter [(value)]="count" />
    <p>Parent sees: {{ count() }}</p>

Now, when the child changes its "value", the "count" signal of the parent also changes. And if the parent sets "count", the child gets the new value.

We can also use a normal property instead of a signal, like "count = 5". Both work.

# ONE-WAY USAGE IS STILL POSSIBLE

Since "model()" creates an input named "value" and an output named "valueChange", we can also use them separately -

    <app-counter [value]="10" />
    <app-counter (valueChange)="onChange($event)" />

# REQUIRED MODELS

Just like inputs, we can make a model required, which means the parent has to bind to it -

    value = model.required<number>();

# MODEL VS INPUT

    - Use input() when the data only flows down, from parent to child.
    - Use model() when the child needs to change the value and tell the parent about it.

A very common use case is custom form-like components such as a toggle, a rating stars component, or a dialog with an "open" state that the child can close by itself.
